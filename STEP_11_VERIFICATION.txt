3. Platform: Architectural refactoring (backend abstraction)

This progression shows developers how to scale from simple to complex widgets
without introducing framework magic—everything is still built from primitives.

========== ARCHITECTURAL INSIGHTS ==========

Widget Building Principles Demonstrated:

1. **Primitives Composition**
   - All widgets built from `draw()`, `row()`, `col()`, `on_click()`, etc.
   - No special widget classes or inheritance
   - Complex widgets are just careful arrangement of simple primitives

2. **State Management Patterns**
   - Simple: Single value (rating: usize)
   - Complex: Collection of values (notifications: Vec<bool>)
   - State flows into view, mutations flow from handlers
   - No global state or side effects

3. **Element Identity**
   - Elements must maintain identity across frame rebuilds
   - `.key()` method provides explicit keying
   - Important for hover/focus/animation state preservation
   - Example: checkbox_group uses key("checkbox-{index}")

4. **Handler Functions**
   - Not closures—take &mut S directly
   - Enables clean state mutation without interior mutability
   - Each interaction gets its own handler function
   - Multiple handlers in one widget work naturally (one per element)

5. **Coordinate System**
   - All coordinates in window-logical units (DPI-adjusted)
   - draw() closure receives Rect in logical units
   - Consistent across all backends (native + WASM)
   - Documented in every coordinate-related function
